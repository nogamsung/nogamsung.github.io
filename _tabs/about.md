안녕하세요. 개발자 **안검성**입니다.

서비스를 만들고 운영하면서 마주친 문제와, 그때 어떤 선택을 했고 결과가 어땠는지를 이 블로그에 기록합니다.

## 하는 일

2023년부터 2025년까지 여행 플랫폼 회사에서 Spring 기반 백엔드를 개발했습니다.
JPA와 Querydsl 성능 개선, Redis 분산 락, Kong API Gateway 도입 같은 이 블로그 초반의 글들은 그때 겪은 일들입니다.

2025년부터는 제조 회사에서 사내 서비스를 만들고 있습니다.
개발 인력이 많지 않은 환경이라 백엔드만 맡는 대신 프론트엔드, 인프라와 배포, 현장에서 쓰는 사람들과 요구사항을 맞추는 일(FDE)까지
IT와 관련된 일은 대부분 제 손을 거칩니다.
한 사람이 전체를 보다 보니 깊이보다 넓이를 먼저 요구받는 날이 많고, 그만큼 모르는 것을 배우면서 결정해야 하는 상황도 자주 생깁니다.
이 블로그의 최근 글들은 그런 상황에서 어떤 선택지를 비교했고 왜 그쪽을 골랐는지를 남긴 기록입니다.

## 다루는 주제

- **Spring Boot / JPA / Querydsl**: N+1 문제, 동적 쿼리, 조회 성능 개선, 버전 업그레이드
- **Redis**: Redisson 분산 락을 이용한 동시성 제어
- **API Gateway**: Kong 설치와 운영, Lua 커스텀 플러그인, Gateway 단 인증 통합
- **배포 / 인프라**: 온프레미스 서버에서의 무중단 배포(Kamal), 컨테이너 운영, CI/CD
- **데이터 / 배치**: Apache Airflow, 분산 환경의 예약 작업
- **SQL**: MySQL 마이그레이션 쿼리와 실행 계획
- **기록**: 컨퍼런스 참관 후기, 연간 회고

## 글을 쓰는 방식

문제 상황을 먼저 설명하고, 선택지를 비교한 뒤, 실제로 적용한 코드와 측정 결과를 남기려고 합니다.
가능한 것은 수치로 검증하고, 실무에서 바로 따라갈 수 있는 수준의 명령어와 설정을 함께 적습니다.
정답이라기보다는 그 시점에 제가 알고 있던 범위에서 내린 결정이라, 더 나은 방법을 아신다면 알려주시면 감사하겠습니다.
